# 헌장 (Constitution)

- 버전 1.0 · 2026-09-17 · 변경은 ADR로만
- 원칙은 요구사항·설계·코드보다 우선한다. 충돌 시 원칙이 이긴다

## P1. 계정 안전 최우선
- 공식 X API v2 + 등록된 개발자 앱 + OAuth 2.0 PKCE 사용자 인증만 사용
- 금지: 브라우저 자동화, 비공식(내부 GraphQL) 엔드포인트, 쿠키·비밀번호 로그인, 다중 IP, 동시 실행
- 속도: 문서화된 한도의 일부만 사용(기본 ≈13%). 무작위 간격. 일일 상한. 활동 시간대 제한
- 이상 응답(401/403/429, 5xx 연속, 잠금 징후) → 즉시 중단·알림. 재시도로 밀어붙이지 않음
- 하드 상한은 코드에 고정. 설정으로 초과 불가. 조정은 "더 느리게" 방향만 자유

## P2. 기본은 dry-run
- 모든 명령의 기본 동작은 계획·미리보기. 실제 삭제는 명시 플래그 + 대화형 확인 + 건수 상한
- 삭제 전 대상 목록을 파일로 출력해 사람이 검토

## P3. 되돌릴 수 없는 작업 전 보존
- X 데이터 아카이브 원본은 읽기 전용 보관. 삭제 대상의 텍스트·메타·미디어 경로를 로컬 DB에 스냅샷
- 삭제 결과(시각·응답 코드·헤더)를 감사 로그로 영구 기록

## P4. 멱등·재개 가능
- 상태의 단일 원본은 로컬 SQLite. 어느 시점에 중단돼도 재실행이 안전
- 같은 항목을 두 번 요청하지 않음. 이미 없는 항목(404)은 완료로 기록

## P5. 관측 가능
- 구조화 로그(JSON Lines) + 사람용 요약. 진행률·잔여 예상 시간·누적 비용 표시

## P6. 확장 지점을 먼저 설계
- 소스(아카이브/API) · 필터(파이프라인) · 액션(삭제/리포스트 취소/좋아요 취소)을 인터페이스로 분리
- 새 필터는 파일 하나 추가로 등록 가능

## P7. 이식성
- Windows 11 우선, 크로스플랫폼 유지. clone 후 3단계(의존성·인증·실행) 이내 사용
- 비밀정보는 OS 자격증명 저장소. 저장소·로그에 토큰 노출 금지

## P8. 문서 규칙
- 개조식 불렛, 간결, 승계 가능(문서만 읽고 이어갈 수 있게), 틀린 내용 0, 읽는 비용 최소
- 결정은 ADR(맥락·결정·이유·대안·결과). 방법론·파이프라인 선택에는 항상 이유를 기록
- 작업 로그는 일자별 1파일. 확정/미정/제안을 구분 표기
