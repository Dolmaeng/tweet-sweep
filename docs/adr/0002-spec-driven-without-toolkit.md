# ADR-0002: 스펙 주도 개발(SDD)을 도구 없이 문서 템플릿으로 적용

- 상태: 확정 · 2026-09-17

## 맥락
- 2026 주류 방법론 SDD: 헌장 → 명세 → 계획 → 작업 → 구현, 단계별 검토. 대표 도구 GitHub Spec Kit, Kiro
- 이 저장소 규칙: 개발 보조 도구의 설정·명령 파일을 저장소 안에 두지 않음. Spec Kit은 `.specify/`와 도구별 명령 폴더를 생성

## 결정
- SDD 산출물 구조만 채택: `docs/spec/00-constitution.md` · `01-requirements.md` · `02-plan.md` · `03-tasks.md`(뒤 2개는 스택 확정 후)
- 도구는 설치하지 않음. 템플릿·절차는 별도 관리 저장소에서 유지

## 이유
- "합의된 문서 → 문서만 보고 구현"이 요구사항 누락·범위 이탈을 막고, 담당자·도구가 바뀌어도 문서만으로 승계 가능(헌장 P8)
- 도구 산출물은 특정 도구에 종속. 문서 템플릿은 누구나 읽을 수 있어 중립적
- 저장소 청결 규칙과 충돌 없음

## 대안과 기각 사유
| 대안 | 기각 사유 |
|---|---|
| Spec Kit 도입 | 저장소에 도구 파일 생성, 명령 체계 종속 |
| 명세 없이 구현 | 안전 수치·확장 지점이 코드에 암묵적으로 묻힘. 검토·재현 불가 |

## 결과·후속
- 단계 완료마다 커밋. 변경은 문서 먼저, 코드 다음
