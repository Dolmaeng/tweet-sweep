# ADR-0005: 코어 라이브러리 + 어댑터(CLI/HTTP) 분리, OpenAPI 계약

- 상태: 확정 · 2026-09-17

## 맥락
- 사용자 진화 경로: CLI → HTMX 대시보드 → TS/React 프론트 → (가능) TS 풀스택. UI가 바뀌어도 안전 엔진은 재검증 없이 유지되어야 함
- 계정 최대 3개를 실행 시 지정. 상태는 계정 id 기준으로 분리

## 결정
- 패키지 3층: `core`(도메인 모델·아카이브 파서·필터·안전 엔진·저장소) / `adapters`(CLI `typer`, HTTP `FastAPI`) / `ui`(HTMX 템플릿)
- `core`는 I/O 프레임워크에 의존하지 않음(표준 라이브러리 + httpx). CLI와 HTTP는 같은 서비스 함수를 호출
- HTTP API는 OpenAPI 스키마 자동 생성 → TS 클라이언트 생성 가능
- 상태 키: 인증된 X 사용자 id. 토큰(keyring 항목명)·DB 파일·로그 폴더 모두 id별

## 이유
- 안전 엔진(페이싱·회로차단·하드 상한)이 UI와 분리되면 테스트가 단순하고, UI 교체 시 회귀 위험 없음
- OpenAPI 계약이 있으면 2단계 TS 프론트는 백엔드 수정 없이 붙음. 3단계 TS 재작성 시에도 계약이 명세 역할
- 계정 사전 등록 없이 "로그인 1 + 아카이브 1"만 입력받는 요구를 id 기반 자동 분리로 충족

## 대안과 기각 사유
| 대안 | 기각 사유 |
|---|---|
| CLI 스크립트 단일 파일 | 대시보드·프론트 추가 시 전면 재작성 |
| 프로필 사전 설정 파일 | 사용자가 원치 않음. id 기반 자동 분리로 충분 |

## 결과·후속
- `02-plan.md`에 모듈 경계·의존 방향. 테스트는 `core` 중심
